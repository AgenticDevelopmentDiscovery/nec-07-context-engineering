## Weaknesses
- `sections/03-content.prose.md` — "Among the repository's files, observable 5 is stated only in `CLAUDE.md`." Verdict: contradicted, by the substrate. At `b9f2176`, `.claude/skills/round/SKILL.md` line 94 reads: "Then **stop**. Do not edit `sections/`, do not commit, do not start another round." The instruction is scoped to the end of a round, but it is a second file that says not to commit, and it reached the window in arm A: runs a-2 to a-5 read the file, and a-1 grepped it and got that line back, all before the first edit. `demo/PROTOCOL.md` lists observable 5 as "CLAUDE.md only", so the error starts there.
- `sections/02-motivation.prose.md` — "A repository usually exceeds the window." Verdict: unsupported. No source is given and the spine carries no tag. The tutorial's own evidence points the other way: the figure shows a 1.0M window with 934.5k free, and the demo substrate is 25 files, 9,900 words.
- `sections/03-content.prose.md` — "Skills is skill descriptions loaded from this repository and the user level." Verdict: unsupported. The capture shows one Skills row with no breakdown by origin. The skills page says Claude Code ships bundled skills and that "Most bundled skills are available in every session". The demo logs list 28 skills in every run's init event; one, `round`, is the repository's, and the rest include bundled ones (`code-review`, `dataviz`) and plugin ones (`anthropic-skills:pdf`).
- `sections/03-content.prose.md` — "A rule in `CLAUDE.md` is ignored. The file is too long, or the rule conflicts with another." Verdict: verified in part, worded more strongly than the source. The memory page lists these two causes among others: the file did not load, the instruction is vague, or it "competes with guidance Claude Code adds on its own". For that last one the page names commit rules and `includeGitInstructions`, which is the case the tutorial's own conflict illustration uses.
- `sections/03-content.prose.md` — "`CLAUDE.md` loads in full at every launch and again after compaction." Verdict: verified for the project-root file only. The page says "Project-root CLAUDE.md survives compaction", and that nested files "reload as Claude reads files they apply to". § The window is a budget you can read has the qualifier; this bullet drops it.
- `sections/02-motivation.prose.md` — the LongPiBench model count. Verdict: verified against the full text, which says "a total of nine LLMs, comprising six open-source and three commercial options". The arXiv abstract page, which is the URL in `references.bib`, says "five commercial and six open-source models" and "robust", not "more robust". A reader who follows the reference sees a different count from the one in the notes. The spine records the second difference, not the first.
- `sections/04-conclusion.prose.md` — "The evidence on length and position comes from retrieval-style benchmarks." Verdict: verified in the main, with one omission. LongPiBench has a Code Completion task, and the paper reports that "absolute position still significantly affects the recall rate in the Code Completion experiments". It is not agentic coding, so the sentence after it stands, but it is the one code result in the cited sources and it is not mentioned.
- `sections/02-motivation.concepts.md` — the dates of the Lütke and Karpathy posts. Verdict: not checked at source. The status IDs in the links Willison gives decode to 19 June 2025 03:01 UTC and 25 June 2025 15:54 UTC, which agrees with the spine in UTC. The dates are not in the prose.
