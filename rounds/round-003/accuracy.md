## Strengths

- Every direct quotation in the prose is verbatim at its source: "the optimal set of tokens", "a finite resource with diminishing marginal returns", "just in time", "under 200 lines", "as a user message after the system prompt", "if two rules contradict each other, Claude may pick one arbitrarily", "expanded and loaded into context at launch".
- The table under § What changed, and what did not recomputes exactly from the logs: reads 17.0 (14–20), 11.6 (9–13), 9.8 (9–11); tokens 47.2k (44.9–50.3), 46.6k (44.7–49.1), 41.3k (39.9–43.1); observables 1–5 at 5 of 5 and the control at 0 of 5 in every arm.
- "Every run copied the sections" holds in the record: all fifteen new prose files open with an HTML comment beginning "Every `##` becomes one slide. One idea each.", which is the template's own comment at `b9f2176`.
- Vendor material is labelled as such where it is used: Hong et al. as "a vendor report", the Anthropic line as "advice, not evidence". The term's origin is worded "gained currency", not "coined".
- The `--add-dir` claim is split between the two pages that support its two halves, and both halves are correct.
- The absence of evidence from agentic coding is stated in the prose, twice, and I found nothing in the four papers that contradicts it.

## Weaknesses

- `sections/03-content.prose.md` § The window is a budget you can read — "`/context` shows current usage as a bar and a table by category" — contradicted by the first page it cites. The commands page reads: "Visualize current context usage as a colored grid." The context-window page says "a live breakdown by category" and names no bar. The bar and table are what the VS Code panel drew in the repository's capture; the sentence does not name that surface, and the conclusion names the CLI version.
- `sections/04-conclusion.prose.md` § Open edges, and where they lead — "How conflicting instruction files resolve is undocumented [@claudecode-memory]" — contradicted as worded by the page cited. The page documents the behaviour: "if two rules contradict each other, Claude may pick one arbitrarily", and of user and project rules, "Neither set overrides the other: if a user rule and a project rule conflict, Claude may follow either one". § Layers has it right: "no documented winner".
- `sections/03-content.prose.md` § Pitfalls — the auto-memory example is filed under "The agent uses something you removed" and "Check what is reachable, not only what is loaded" — unsupported as classified. The memory was not removed and was not merely reachable. The memory page says auto memory is "Per repository, shared across worktrees", and that the first 200 lines or 25KB of `MEMORY.md` "are loaded at the start of every conversation". The dry run was in a worktree of this repository, and its init event gives this repository's memory folder as `memory_paths.auto`. It is documented loading.
- `sections/03-content.prose.md` § What `/context` shows at launch — "Skills is skill descriptions loaded from this repository and the user level" — unsupported. No record lists the skills in that session. The skills page says bundled skills are included with Claude Code and the settings reference says they are enabled by default; the init event of every demo run on the same machine lists 28 skills, of which one (`round`) is the repository's, with bundled (`code-review`, `doctor`, `claude-api`) and plugin (`anthropic-skills:*`) entries among the rest.
- `sections/03-content.prose.md` § What changed, and what did not — "One B run of five" and "Four A runs of five" — verified against the logs, but neither count is in `demo/RESULTS.md`, which the house convention makes the only source for demo numbers. `RESULTS.md` says "Arm B justified choices by citing `CLAUDE.md`", which reads as the whole arm.
- `sections/03-content.prose.md` § What changed, and what did not — "Among the repository's files, observable 5 is stated only in `CLAUDE.md`; no run committed, in any arm" — true as scoped, with no source for why arm A complied. The settings reference says of `includeGitInstructions`: "Normally Claude Code includes instructions for writing commits and pull request descriptions", default "unset, so the built-in instructions are included". The memory page, already in `references.bib`, points to the same setting. The prompt also asked for no commit.
- `sections/02-motivation.prose.md` § Why agents make the window the bottleneck — "A repository usually exceeds the window" — unsupported; untagged, no source. The demo substrate is a counterexample: the template commit is 25 files, 61,155 bytes and 9,900 words, against the 1.0M window in the tutorial's own capture.
- `sections/03-content.prose.md` § What `/context` shows at launch — "The harness controls System tools and System prompt" — unsupported; untagged, no source.
- `sections/02-motivation.prose.md` § How a window fails — "most current models robust" — outdated. "Current" is the paper's word, first submitted 18 October 2024. The body names the commercial models tested: Gemini-1.5-Flash, Claude-3-Haiku and GPT-4o-mini. The body is also weaker than the abstract: "most current models are more robust", and "some open-source models like Qwen 2.5 (7B) still suffer heavily". The abstract page says "five commercial and six open-source models"; the body says three and six.
- `sections/02-motivation.prose.md` § How a window fails — "performance degrades as input grows, even on simple tasks" — undated, present tense, two citations. Hong et al. tested 18 models current in July 2025; Modarressi et al. tested 13, among them GPT-4o, Gemini 1.5 Pro and Claude 3.5 Sonnet. "Even on simple tasks" is Hong et al.'s phrase only; NoLiMa is built to be harder than literal matching. The demo ran on `claude-fable-5-1`, which neither tested.
- `sections/04-conclusion.prose.md` § Open edges, and where they lead — "as documented on 28 and 29 September 2026, for Claude Code 2.1.281" — the pages are living and unversioned. As read today they describe features that need v2.1.283 (`/doctor prompt-audit`). The `/context` figure came from a session with extension 2.1.284 and CLI 2.1.281 installed, and `demo/RESULTS.md` says the panel shows neither. 2.1.281 is the version of the demo runs only.
- `sections/03-content.prose.md` § What changed, and what did not — "saved no tokens" — stronger than the table beside it, where B's mean is 46.6k against A's 47.2k. What the record supports is that the ranges overlap.
- `demo/RESULTS.md` § Threats to validity, carried into `sections/03-content.concepts.md` § The demo and `topic.md` § Open questions — "The `/round` skill description was in the window in every arm" understates the record: 28 skill descriptions were listed in every arm.
